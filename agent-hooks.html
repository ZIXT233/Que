共同规律

命名不同，边界相同。各家用不同的名字标注同一批边界：回合开始（beforeSubmitPrompt / UserPromptSubmit / BeforeAgent / PreInvocation）、工具前后（PreToolUse / BeforeTool…）、回合结束（Stop / sessionEnd / AfterAgent / agent_settled）。


两类询问要分清。Antigravity 与 Cursor 的工具 hook 在「用户是否被询问」上是同一个事件、无法从载荷分辨——直接当询问处理会在每次读文件、每次 grep 时报警。可靠的做法是：先按「工作中」处理并挂起猜测，工具毫秒级自动放行则后续事件冲销；若超过窗口（如 5 秒）仍无下文，才升级为真实的「需要人介入」。


子 Agent 事件一律丢弃。凡载荷携带子 Agent 标识（如 agentId）的事件，与队列状态无关。


旁观的 hook 不设闸。凡要求 stdout 回裁决的 hook（如 Cursor），一律返回放行——观察者不应阻塞 CLI。
