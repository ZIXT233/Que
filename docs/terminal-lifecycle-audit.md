# 终端状态与生命周期

日期：2026-09-22。本文对应当前工作区源码。用户随后授权命令行构建测试，验证结果见末节；未启动应用或做 UI 验证，不能据此认定持续停刷已经修复。

## 1. 一个终端包含哪些对象

同一页面内，一个 terminal ID 对应固定的 portal host、TerminalPanelView 和池中的 TerminalSession。队列与浮层注册展示插槽，移动的是已有 DOM，不是创建第二个终端。

后台 PTY 与前端对象分开生存：暂停输出订阅、回收 WebGL、销毁前端缓存都不等于终止后台进程。独立窗口是另一 WebView，会有自己的前端实例，不能跨窗口共享 DOM 或 JS 实例。

| 层 | 唯一职责与入口 | 不负责 |
| --- | --- | --- |
| CardQueueShell | 决定卡片在队列、浮层或工作区的位置 | 不直接开关 SSE 或发送终端焦点协议 |
| PersistentTerminalViews | 合并插槽注册和注销，选择最终位置，移动固定 host | 不连接后台，不操作 xterm 缓冲 |
| TerminalPanelView | 将展示需求交给 session；位置变化通知布局 | 不自行恢复连接或重建历史 |
| TerminalSession.reconcileView | 依据最终展示需求统一控制订阅需求、输入许可、焦点报告与 GPU 生命周期 | 不决定卡片业务阶段 |
| TerminalSession.connect / scheduleReconnect | 建立与重试当前输出连接，验证回调归属 | 不决定队列或浮层位置 |
| refreshPlacement / fitAndResize | 主题、字体和实际尺寸；resize 按尺寸去重 | 不开关连接，不因迁移强制重画 |
| Rust terminal hub | 后台进程、输出记录、进程退出 | 不依赖 React 视图是否挂载 |

## 2. 状态不是一个可以任意互推的布尔值

| 字段 | 定义 |
| --- | --- |
| card.phase | 业务进度；working 不能推出终端应该隐藏 |
| active | 上层选择该视图用于展示；不是严格的像素可见性，也不是 OS 键盘焦点 |
| attached | session 仍有 React 视图持有；停放的视图也可能 attached |
| presented | session 已应用的最终展示需求；同一轮挂载/卸载先合并再应用 |
| live | 输出订阅需求；不代表网络已连接 |
| connected | 当前 EventSource 已打开；不证明输出已解析或画面已绘制 |
| exited | 后台报告退出或关闭；停止后续连接，保留最后画面 |
| inputFailed / startFailed | 输入或启动失败；独立于展示位置 |
| gpu | 可选 WebGL 渲染器；回收它不清空 xterm 缓冲 |
| destroyed | 前端 session 已销毁，不可继续接收回调 |

`inQueue` 不再进入 session 的控制参数。当前焦点协议继续沿用“选中展示”的策略，并对相同报告去重；这不是完整的浏览器焦点模型，也不能把它解释为实际键盘焦点。

## 3. 转移规则

| 事件 | 连接 | xterm 与画面 |
| --- | --- | --- |
| 可见队列 → 可见浮层，或反向 | 展示需求保持 true，不因迁移暂停或重连 | 保留实例、缓冲与 GPU，只测量布局 |
| 真正隐藏或没有持有视图 | 暂停订阅，保留输出游标 | 保留缓冲；300ms 后若仍隐藏，回收 GPU |
| 隐藏 → 选中展示 | 按已有输出游标续接 | 加载 GPU、测量布局；不主动 reset |
| 网络失败或输出缺口 | 当前连接关闭，按游标重试 | 保留已有缓冲；缺口也清除 connected，禁用输入 |
| 后台退出 | 关闭当前连接，不重试 | 保留只读最终画面 |
| 明确重连或不可复用的 session | 释放前端 session 后重建 | 从后台输出记录恢复；不属于位置迁移 |
| 用户关闭终端 | 停止输入，请求 DELETE 后回收 | 与隐藏、移位明确区分 |
| 缓存淘汰 | 关闭被回收前端的连接 | 销毁前端实例；不删除后台 PTY |

服务端若已裁剪掉客户端缺失的输出，续接仍可能收到 reset 全量回放。这是后台记录的边界，不是位置迁移主动清空屏幕。

## 4. 队列到浮层的交接顺序

1. 业务层把卡片移出队列并打开浮层；不把 working 卡片重新塞回队列。
2. 旧插槽注销，浮层在 layout effect 测量后注册新插槽。
3. 位置管理器在 microtask 中统一选择插槽，浮层优先；随后移动 host 并发布最终 active。
4. session 也合并本轮 attach、detach、选项变化，再由 reconcileView 应用最终展示需求。
5. 若仍为 active=true，连接开关不发生变化。placementVersion 只触发布局测量。

这里的批处理覆盖当前同步提交及 layout effect 交接，不是任意时长的“迁移中”状态。如果未来把新插槽注册改成异步等待数据或动画，必须显式设计交接所有权，不能靠延长定时器来猜测是否还会出现新插槽。

## 5. 本次源码调整

- 插槽注销不再立即发布 active=false；位置与停放判断统一延后到本轮注册完成。
- 视图引起的 setLive 只有 reconcileView 一个调用点，去掉 detach 的 200ms 连接宽限定时器。
- refreshPlacement 去掉连接恢复、GPU 加载和强制重画，仅处理布局相关工作。
- 焦点报告在最终展示状态确定后发送，同一状态不重复报告。
- EventSource 的 message/open/error 均检查对象是否仍为当前连接；暂停、离线和退出清除连接引用，使旧回调失效。
- reconnect 清除旧重试定时器；重试与新建连接时先清除 connected，避免旧就绪状态继续允许输入。
- 隐藏状态下输入禁用；readOnly、关闭、退出与输入失败仍分别参与许可判断。

## 6. 仍需区分的边界

- provider 保留最多 32 个无插槽视图，pool 另保留最多 32 个无视图 session；这是两个缓存层，不是后台会话数量上限。
- 改变不兼容的会话参数、输入失败后的再次 acquire、明确重连和缓存淘汰都可能重建前端；普通位置迁移不走这些路径。
- 输出探针现有 bytesWritten / lastOffset 表示收到并排队，不代表 xterm.write 已完成，更不代表已绘制。此次没有补做解析/绘制探针。
- writer.lastSize 是本窗口的尺寸记录，独立窗口互相改变同一后台 PTY 尺寸的边界仍存在，此次未修改。
- 当前改动消除了源码中多处控制连接和交接中间态的问题。持续停刷究竟发生在后台输出、当前 SSE、xterm 解析还是绘制层，仍需运行时证据。

## 7. 用户运行时核对路径

依次观察：回复后队列转留意浮层且持续输出；关闭浮层后再次打开；输出结束后浮层回队列；切换选中卡片；网络恢复；进程退出；明确重连与关闭。分别核对内容连续、没有额外清屏、输入许可和最终退出画面。以上为待验证路径，不是已通过的测试。
