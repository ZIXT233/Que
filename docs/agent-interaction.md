# 卡片之间的消息

一张卡的 Agent 可以给另一张卡发消息，就像你在那张卡里打字，只是署名是发送方的卡片。前后端两台机器上的 Agent 联调、管家转达你的任务，都用这一种机制。

## 消息

- **消息是一段文字**，带发送方卡片的名字和编号，不带发送方的对话历史或文件。
- **每张卡有一个收件箱**（`mcp/inbox.json`，Que 管理）。`send_message` 把消息放进对方的收件箱就返回。
- **每条消息只交给对方一次**，哪种方式先到算哪种：
  1. 对方**空闲**：消息成为对方的下一轮，开头写明来自哪张卡（`runtime/session-history.mjs`）。没连接的卡会先连接。
  2. 对方**正忙**：随它下一次调用任意 QueACP 工具的结果交给它（`queacpMessages` 字段），或者它调用 `wait_messages` 时交给它。ACP 不能往运行中的回合插入输入，这是最接近"在两次工具调用之间读信"的办法。
  3. 都没赶上：对方这一轮结束、空闲后，按第 1 种交付。
- **回复也是消息。** 没有自动回传：对方要回复，就用 `send_message` 发回来。消息头会告诉它"回复请 send_message 到卡片 X"。
- **等回复**：发送方要在本轮里拿到回复，就调用 `wait_messages`（默认等 50 秒，最多 120 秒，可以反复调用）；不等的话就结束本轮，回复到达时会成为它的下一轮。不要用 `read_session` 轮询。

## 防循环

两个 Agent 可能一直互相回复。和邮件服务器一样，用机制兜底，不靠语义规则：

- 同一发送方 10 分钟内给同一张卡发相同内容，拒绝；
- 同一发送方 10 分钟内给同一张卡发超过 20 条，拒绝，并提示合并成一条或去问用户；
- 每张卡的收件箱最多 50 条未交付消息，超出时丢掉最旧的；
- 同一个 `requestId` 的重试只会投递一次，不受上面的限制。

## 权限

- 所有卡片都是你自己的，卡片之间发消息、读会话、取消回合**不需要批准**。
- 消息来自别的 Agent，不是你。它不能批准任何权限请求或回答表单，这些只能由你在卡片里处理；收件方自己的权限设置照常生效。
- 新建、归档卡片，修改设置和工作区，只有管家能做。卡片只能改自己的昵称，管家可以改任何卡的。

## 界面

别人发来的消息画在 Agent 一侧，浅蓝底色，标着"来自 某卡"。不管它是作为一轮到达，还是随工具结果交付，样子都一样。工具结果里的消息只在当场可见：acpx 记录不保存工具输出，重启后历史里只能看到作为一轮到达的消息。

## 远程 MCP：复用现有 SSH 通信

链路为：远程 Agent → stdio MCP 桥 → 远程 owner 的专用本机 IPC socket → 当前 SSH exec 标准输出 → 本机 QueACP 工具服务；结果从同一 SSH exec 标准输入返回。没有新增 TCP 监听、SSH `-R`、公网接口或防火墙设置。远程主机仍需要原有 SSH 登录和 Node 环境。

- 桥接代码随 ACP runtime 自动部署，Agent 会话通过 ACP 的 `mcpServers` 获得工具。不改用户全局 Agent 配置。
- 每次 Agent 启动生成独立的 MCP capability，只能代表该卡片当前运行。此凭据不进入会话快照和绑定文件；本机 MCP 总令牌不下发。
- 专用 IPC socket 只接 MCP 请求，与可执行 ACP 控制命令的 owner socket 分离，Unix 权限为 `0600`。
- 本机根据实际 SSH 链路核验主机、注册工作区、来源卡片、当前运行和连接代次，再执行与本机相同的工具逻辑。远程卡片不会成为管家。
- 请求使用独立编号，工具请求与普通 ACP 回复并行处理。结果只返回发起该请求的 relay，不向其他连接广播。
- 每次调用有时限：一般 20 秒左右，`wait_messages` 按它要求的等待时间放宽。
- 连接断开或替换会使等待中的调用失败；不自动重放工具操作。结果不确定时先查状态，不能另造请求编号重新发送。
- 建立新连接后，QueACP 为该主机上已注册的活动卡片恢复 MCP 路由；仍在运行的 Agent 无须重建即可发起新调用。未确认的旧调用不会随恢复重新执行。
