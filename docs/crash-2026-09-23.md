  exception `0xc000001d`, RVA `0x29ef99`; dump `que.exe.30932.dmp`.
- Installed and release EXEs have identical `.text`, `.pdata`, `.data`,
  `.rsrc`, `.reloc`, PE timestamp `6ab2b079`, and RSDS GUID
  `BD225B1C-55A4-427A-817A-99436F31DEBB`, age 1. Whole-file hashes differ
  in `.rdata`; that does NOT mean this is a different code build.
- Exception thread 49020; RIP = module base + `0x29ef99`. The function's
  unwind entry spans RVAs `0x29ee50..0x29efa4`.
- The function clones a 136-byte runtime Context. At RVA `0x29eed0` it
  increments `[rsi]` without `lock`; if that wraps to zero it jumps to the
  faulting `ud2`. The dump's registers have advanced through the previous
  atomic increment, but not the subsequent `rbx` assignment. This identifies
  the non-atomic counter branch rather than an unsupported CPU instruction.
- A diagnostic build of the unpatched library with LLVM IR and line tables
  identifies this exact field layout and operation as
  `tauri_runtime_wry::Context<tauri::EventLoopMessage>::clone`, offset 48,
  inlined through Tao's Windows `EventLoopWindowTarget::clone` and `Rc::clone`.
- The matching release PDB has only sparse public symbols. Nearest-symbol
  answers with multi-megabyte displacements are not usable function names.
- No Rust panic report was written. This trap bypasses the normal panic hook.

## Defect and correction

Tauri runtime-wry 2.11.4's `Context` derives Clone and embeds
`DispatcherMainThreadContext` by value. That wrapper is manually Send + Sync,
but includes Tao 0.35.3's Windows target, which owns an `Rc<EventLoopRunner<T>>`.
Cloning/dropping dispatchers across threads therefore mutates a non-atomic
reference count. Actual event-loop access guards do not protect Clone/Drop.

The Windows Cargo patch stores the payload in an owner-thread registry. Context
copies carry only an ID and atomic liveness flag, never the Tao target. A non-Send
guard invalidates handles and releases the payload before Wry's event-loop field
is destroyed. The payload no longer has unsafe Send/Sync on Windows. This removes
the cross-thread refcount path matching the crash branch. The dump lacks the heap
allocation, so the exact earlier racing operations cannot be reconstructed.

During the crash investigation, release builds retained debug information and
PDB symbols (`debug = 1`, `strip = false`). After the runtime fix, normal release
builds reverted to `debug = 0`, `strip = true` on every platform to avoid shipping
debug information in installers. For a future investigation, explicitly enable
symbols for that diagnostic build and keep its EXE with the matching PDB.

### Follow-up lifecycle audit

The initial Arc-only mitigation was replaced because its final worker-held
reference could destroy the payload on that worker. Registry handles do not own
the payload. Owner-local in-flight references may finish after invalidation, but
cannot move to workers. Debug avoids the payload, monitor getters dispatch to
the event loop, and new calls reject invalidated handles. This is a Windows-only
ownership fix, not a complete audit of upstream unsafe code or other platforms.
