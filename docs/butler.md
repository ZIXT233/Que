# Butler

主内容区左下角圆形按钮召唤唯一的 Butler 卡片，复用聊天、卡片和 Agent 连接。标题栏为金色。首次使用 Codex，以后恢复原会话。点击不会发送提示或创建重复卡片。

固定本机工作区：`~/.flat/butler`，开发版也使用该路径。会话仍由 acpx 保存，不另建聊天数据库。

随二进制嵌入并在启动时安装：

| 文件 | 所有权 |
| --- | --- |
| ROLE.md、AGENTS.md | Flat 管理，每次更新同步职责 |
| USER.md | 用户明确的偏好与授权，仅首次创建 |
| MEMORY.md | 长期事实和决定，仅首次创建 |
| STATE.md | 当前事项与卡片索引，仅首次创建 |
| notes/ | 按需加载的细节与来源 |

公开分发的默认上下文只包含 Flat 使用说明、管家职责、权限边界和记忆规则，不包含开发者或任何用户的个人画像。USER.md、MEMORY.md、STATE.md 初始为空白说明；用户使用中明确提供的信息仅写入其本机记忆，不回写分发模板。

每次发送到 Butler 的消息附带内置职责，避免仅依赖某个 Agent 对 AGENTS.md 的支持。聊天界面保留原始消息。管家按需读取记忆；内置职责不授予自主决策或代理审批权限。

Flat MCP 核验固定卡片、工作区、路径、存活会话及连接代次后，允许其访问所有卡片。其他 Agent 不继承该授权。监听由应用自动维护，涵盖未归档的本地和远程 Agent 卡片及后续新增卡片；没有会话的空白卡片在启动后纳入。完成、失败、取消、待确认事件使用持久订阅队列，忽略通知产生的回合，避免通知循环。

关闭 Butler 会话或归档后暂停投递；再次召唤时恢复。远程不可达时无法获取实时状态。仅接收通知不表示任务完成或授权继续工作。访问权限不代表自动批准目标 Agent 的系统权限。

## 卡片生命周期工具

- `list_workspaces()`：列出已保存工作区，包括本机和 SSH。
- `list_harnesses(workspaceId)`：查询该机器的 Harness 标识。
- `create_card(workspaceId, kind, requestId, nickname?)`：在现有卡片堆中新建并启动会话，返回 cardId/sessionId。需要调用者具备全卡片权限；Butler 默认具备。不会复用用户的空白卡片。任务文本通过已有 send_message 另行提交。
- `archive_card(cardId, requestId)`：关闭闲置会话并归档，保留历史；执行、排队或独立窗口中的卡片不能直接归档，不能归档调用者自己。

新建使用来源和请求 ID 确定唯一卡片，参数摘要随卡片持久化；启动失败返回已创建的卡片 ID，可用完全相同的请求重试。归档回执也随卡片持久化，旧请求重试不会再次关闭后来恢复的卡片。普通 Agent 未获全卡片授权时不能调用上述写操作。

验证：51 项 Rust 单元测试、MCP 工具发现及 ACP 运行时回归通过；真实本地 MCP 调用验证创建、重复创建、归档、重复归档，未向 Agent 发送测试任务。SSH 创建沿用已有启动链路，本轮未做远程创建验收。
